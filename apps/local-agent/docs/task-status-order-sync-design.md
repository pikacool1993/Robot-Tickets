# 终端任务状态与出票信息同步需求定稿

确认日期：2026-11-21。适用范围：local-agent、cloud-server 与云端管理界面。需求、cloud-server API/存储、管理员展示及 local-agent 本地队列接入已落地；无真实购票订单时未进行完整云端现场联调。

## 目标

local-agent 接入时机：客户端登录并初始化协议后首次发送完整任务快照；之后在任务/授权状态变化时合并快照。订单创建成功后将记录写入独立本地加密队列，沿用订单创建后的首次详情查询；详情成功上传 complete，查询失败上传已有信息并标记 unavailable。待发记录按服务器、代理商和终端实例隔离，退出、换号或删除本地订单不清除待发数据。后台每秒检查一次，不在库存命中或下单请求路径执行网络上传；失败使用 5/15/30/60 秒退避。

- 云端按终端展示任务总数及微信授权状态分类数量，并能查看该终端的具体任务。
- 云端保存终端创建订单后的出票信息，供订单所属代理商查询。
- 同步仅由任务授权状态变化和订单创建触发，不做周期性全量轮询。

## 任务状态同步

- 每个终端同步当前任务总数和任务条目；管理界面可以使用状态标签展示，不要求采用表格列表。
- 每个任务至少关联终端编号、任务编号和授权状态。状态变化时上传新状态及发生时间。
- 状态分类：在线、授权失效、待授权、协议离线、维护暂停、状态未知。状态数量由当前任务条目归类汇总，任务总数应与各分类数量之和一致。
- 删除任务时同步删除/撤销该任务的当前状态条目，使终端当前任务总数及时更新；该行为不影响已同步出票记录。
- 终端或网络暂时不可达不等同授权失效。云端可标记终端最近通信时间，但不得自行推断微信授权状态已失效。

## 出票记录

订单创建后，客户端先按现有订单详情查询流程等待结果，再生成唯一的云端订单记录：

- 订单详情响应成功：上传完整信息。
- 详情查询流程结束仍失败：上传创建时已有信息，并标记订单详情未获取；该订单不另建第二条记录。
- 订单详情查询可用时，信息包括场次、票数、票档、精确排号和座位号、出票时间、支付截止时间、订单号、观演人姓名和电话、终端编号、任务编号及代理商名。
- 详情不可用时，上传所有已取得字段，未取得字段留空并标记详情未获取，不以请求方案中的座位要求冒充实际出票座位。
- 出票时间采用订单创建时间；过期时间采用订单详情中的支付截止时间。时间以带时区的标准时间戳传输，管理界面按北京时间展示。
- 本地模拟验收订单也通过出票同步接口上传，设置 `simulated:true` 并在管理员订单页明确标识；模拟详情只使用本地生成的数据，不调用真实订单详情接口。
- 终端编号、任务编号和代理商名用于追溯。云端必须从已认证的终端会话确定代理商归属，不信任客户端自行填写的代理商身份。

## 送达、去重与删除

- 网络失败或客户端退出时，尚未确认送达的授权状态事件和订单记录在本地持久化暂存；联网并重新认证后自动重试。
- 重试可以重复发送，但云端只保留一条逻辑订单记录。云端使用认证终端实例标识与订单号构成幂等键；重复请求返回/更新同一记录，不重复插入。
- 授权状态同步按任务和事件版本/发生时间处理，较旧的迟到状态不得覆盖较新状态。
- 用户删除 local-agent 中的本地订单记录，不删除云端已接收的出票记录。删除客户端任务只移除云端当前任务状态，不级联删除出票历史。

## 查看权限与个人信息

- 订单所属代理商可查看其名下订单完整信息，包括观演人姓名和电话；其他代理商不可见。
- 云端管理员默认看到脱敏后的姓名和电话。经明确的业务授权操作后才可查看完整信息；查看行为写入审计记录。
- 订单查询、导出和详情接口均执行服务端代理商隔离与管理员权限校验，不能只依赖前端隐藏字段。

## 验收要求

- 授权状态变化触发同步，云端任务总数和状态标签数量与终端一致；同一状态重复上报不造成重复任务。
- 终端删除任务后云端当前任务统计更新，但相关出票记录保留。
- 订单详情成功时记录包含真实的排号、座位号和支付截止时间；详情流程失败时只上传已有信息并标记详情未获取。
- 断网后事件能补传；传输重试和客户端重启均不会造成重复订单记录，迟到的旧状态不会覆盖新状态。
- 所属代理商可查看完整出票数据，其他代理商被拒绝；管理员默认脱敏，授权查看产生审计记录。
- 模拟订单进入云端出票记录并在管理员订单页显示“模拟订单”标识；模拟流程不执行真实购票操作。
