# N1 / N5 HTTP 代理池

客户端侧边栏 IP 池页分别管理 N1、N5。手动批量录入 `IP|端口|用户名|密码|YYYY-MM-DD`；同一列表按 IP+端口去重，重复/错误行提示行号并跳过，有效行正常保存。到期日期按北京时间当天结束计算。凭据沿用 Store 的 Windows DPAPI 加密，列表不返回密码；编辑密码留空保留原值。

首次请求时优先分配绑定任务较少的可用出口，并保持任务绑定。代理过期、停用、删除或冷却后，下一次请求重新分配。停止且无在途下单时释放绑定；读取视图不创建新绑定。代理配置持久化；出口、失败计数、冷却仅保存在内存。

每个接口有独立的“全部任务使用本机直连”和“本机直连参与分配”。前者优先；后者把本机作为一个分配候选。无可用代理始终回退直连。

N1 累计连续网络失败（含代理认证失败），N5 仅累计连续超时。正常响应清零，换出口清零；默认阈值3、冷却60秒，可分别配置。计数按任务+出口，达到阈值后在对应池全局冷却代理。本机不冷却。在途请求带分配代次，旧请求结果不覆盖新分配。响应正文读取超时也计入。

单任务/全部任务随机切换同时处理 N1、N5，遵循直连开关，优先排除当前出口，无其他候选时保留原出口。切换只影响后续请求，不增加业务请求。

N5 超时继续现有下单循环与间隔，不进入核实状态。请求层不自动重放 N5 POST。任务明确停止时不再继续下单。

单条测试与测试全部只通过该代理对目标域名发 HEAD / 请求，验证 HTTPS 连通性，不调用业务 API。批量测试最多并发3个；展示结果、耗时、测试时间，不改变绑定、失败计数、冷却或启停状态。连接成功不代表业务接口可用。

验证：go test ./...；pnpm --dir frontend build。代理传输测试使用本地 HTTP 代理验证 CONNECT 与 Proxy-Authorization；未向真实票务下单接口发送测试订单。
