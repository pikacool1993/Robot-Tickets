# 完整模拟验收

模拟验收仅用于验证 local-agent 任务状态机、下单处理、订单列表和售后页面，不连接官方库存及订单写接口。真实任务和模拟任务不能同时运行。

## 启用与准备

1. 先退出客户端，在 PowerShell 中设置环境变量并启动：

   ```powershell
   $env:ROBOT_DEBUG = "1"
   .\local-agent.exe
   ```

   开发模式可在 `apps/local-agent` 目录执行 `$env:ROBOT_DEBUG="1"; wails dev`。关闭该 PowerShell 后变量自动失效。必须从这个终端启动客户端，已运行的客户端不会读取后来设置的变量。

2. 在客户端完成登录、业务登录，确认协议账号在线，并为要验收的任务选择观演人、设置票类或区域。
3. 停止所有真实库存任务。在“设置”中启用“本地模拟验收”，按目标场景配置概率并保存。
4. 模拟任务使用本场开售时间调度，允许提前启动等待。各任务可以点击卡片上的“模拟验收”；也可点击顶部“批量模拟验收”启动全部符合条件的任务。启动模拟之前须已完成客户端时间校准及比赛配置。

## 库存响应

库存五种场景的概率合计为 100%，默认值如下：

| 响应 | 默认概率 | 模拟行为 |
| --- | ---: | --- |
| 有库存 | 35% | 根据阶段随机票区和数量 |
| 空库存 | 30% | `code=1`、可购买按钮状态、无票区数据，提示“已售罄” |
| 按钮不可购 | 15% | `code=1`、`btn_status=0`，提示“暂未开售” |
| 网络异常 | 10% | 模拟查询超时 |
| 业务异常 | 10% | 从 `-1、996、997、998、999、200、1234` 中均匀抽取 |

每个模拟任务的第一轮库存响应（包括启动较晚、首轮立即查询）及开售后一分钟内的所有查询，都原样返回 `config/bill-regions.json` 完整数据，不受库存概率影响，也不随机修改数量。首次查询依然遵循正式调度：开售时间后 1 秒发起；已过该时刻则立即查询。

开售后 1 至 2 分钟，抽到“有库存”后模拟初始放票：随机选择约 60% 的具体区域，各区随机数量约为其样例库存上限的 10% 到 100%。开售满 2 分钟后模拟少量回流：每次随机选择 2 到 4 个有库存区域；约 80% 的被选区域有 1 或 2 张，其余情况有 3 到 5 张。样例上限低于随机数时按样例上限截断。票区、区域 ID、票类及价格沿用样例，分组库存汇总按随机后的区域数量重算。不同响应独立随机，不会在模拟下单后扣减库存。

库存场景概率控制是否返回对应类别；进入有库存场景后再由时间阶段规则决定哪些区域有多少张。命中后仍按任务自己保存的观演人、票类/区域和跨区设置匹配，不能匹配时不会下单。

## 下单响应

下单成功与 12 种失败／特殊响应各自单独设置概率，13 项合计必须为 100%；为 0% 的项目不会出现，为 100% 则可固定验收该响应。旧版只设置成功率的配置会迁移为剩余概率近似均分到 12 种响应。

12 种下单结果依次为：

| 序号 | 模拟响应 | 沿用客户端处理 |
| ---: | --- | --- |
| 1 | `code=3` 库存不足，无 timeout | 默认等待 5.6 秒后恢复轮询 |
| 2 | `code=5` 抢座失败，无 timeout | 模拟返回额外附带随机 `delay` 5–12 秒，等待后恢复轮询 |
| 3 | `code=1` 但无订单 ID | 进入订单核实中，同任务不再下单 |
| 4 | 您有未支付的订单 | 购票已暂停，显示原始提示 |
| 5 | 此身份证已购买过本场比赛门票 | 购票已暂停，显示原始提示 |
| 6 | 您已超过最高购票量 | 购票已暂停，显示原始提示 |
| 7 | 请求超时 | 等待 1 秒后恢复轮询 |
| 8 | 响应无法解析 | 等待 1 秒后恢复轮询 |
| 9 | `code=3, timeout=2` | 等待返回的 2 秒 |
| 10 | `code=5, timeout=2` | 等待返回的 2 秒 |
| 11 | 连接中断 | 等待 1 秒后恢复轮询 |
| 12 | 其他业务错误 `code=996` | 默认等待 1 秒后恢复轮询 |

需要注意：第 2 项 `code=5` 带正数 `delay`，实际使用随机 5–12 秒，而不是未带 delay 时的 3 秒默认等待。对于购票暂停，任务不会自动恢复；订单核实只有人工确认官方端没有创建订单后才能解除。

成功响应按设定概率生成本地 `SIM-...` 订单，不访问官方下单接口。另有“已付款概率”独立决定模拟订单初始显示待支付或已支付。

## 查单与售后

成功订单保存在应用本地订单库，标记“本地模拟订单”，使用 `LOCAL-SIMULATION` 占位 token。订单页、详情和状态与正式订单共用同一界面。模拟订单查询、取消和退款均只操作本地数据。

查单、取消、退款分别配置失败概率，彼此独立。失败时提示模拟接口错误，不改变订单状态；将对应失败率设为 100% 可稳定检查错误反馈，设为 0% 可检查成功路径。

- 已付款概率设为 0%，下单成功后可验收待支付订单详情及“取消未支付订单”。
- 已付款概率设为 100%，下单成功后可验收已支付订单详情及“整单退款”。
- 退款成功后模拟订单显示已退款，票券移入已退明细；取消成功后显示已取消。
- 手动刷新订单详情及售后操作前的状态检查继续执行；模拟接口失败时不会执行状态变更。

## 推荐操作

确定性检查全流程成功：

1. 库存有库存设 100%，其余库存响应设 0%。第一轮和开售后一分钟的完整样例仍优先于概率设置。
2. 下单成功设 100%，其余 12 项失败响应设 0%。
3. 查询、取消、退款失败概率设 0%。
4. 已付款概率设 0% 验收取消；设 100% 验收退款。若当前任务的首次查询受一分钟完整样例规则影响，样例库存不满足任务要求时需等待概率响应阶段，或调整比赛开售时间后重开任务。

定向检查指定业务响应：

1. 停止全部运行中的模拟任务后打开设置。
2. 将目标下单响应设为 100%，其他 12 项（含成功）设为 0%，保存并重启一轮模拟任务。
3. 验证卡片状态、原始服务端提示、日志和是否按规则恢复；检查购票暂停与订单核实分支时分别使用对应响应。

库存回流检查：将库存有库存概率设为 100%，空库存、按钮不可购和两种异常设为 0%；首轮和开售一分钟内仍会返回完整样例，之后观察 1–2 分钟充足阶段与两分钟后的少量回流阶段。客户端统一查询间隔默认 300–800 毫秒，运行中的任务不能修改设置，调整概率前先停止任务。

## 隔离与注意事项

- 模拟订单的库存查询、创建、详情、取消、退款响应使用 `SIM-N1`、`SIM-N5`、`SIM-ORDER` 日志标记。不得以日志外观代替真实服务器联调。
- 模拟运行期间后端拒绝启动真实库存任务；库存广播只发生在同模式任务之间。模拟任务复用真实匹配、密钥等待、请求加密签名和状态处理代码；在 N5 发送前拦截，请求不发往官方下单服务器。DEBUG 开启时，完整链接和 JSON 请求体写入任务日志，并标注“模拟验收拦截 N5（未发送）”。模拟不会验证官方服务器是否接受这些参数。
- 业务账号登录、协议授权及观演人刷新本身仍使用现有业务服务；模拟不会替代授权链路测试。
- 停止任务不会删除模拟订单。模拟订单长期保留在本地，可从订单页手动删除；客户端重启不自动恢复任务或自动查询订单。
- 完成验收后，停止所有模拟任务并关闭“本地模拟验收”。生产启动不要设置 `ROBOT_DEBUG=1`。
