# 任务定时刷新需求定稿

确认及实现日期：2026-11-20。范围仅为 local-agent。本文件是实现与验收依据；定时调度、设置和任务状态展示已接入，沿用现有手动维护流程。验证使用本地桩，不包含官方真实库存与订单联调。

实现参数：默认关闭，默认间隔 30 分钟，可设 1～1440 分钟；全局最多一个自动维护流程，两次启动至少间隔 2 秒。首次开售前 30 秒进入避让窗口，直到首次提交状态退出。临时失败按 5 秒、15 秒、30 秒、60 秒退避，后续保持 60 秒；等待配套加密参数超过 5 分钟转入失败重试。所有时间均为客户端调度选择，不代表官方会话有效期。

## 全局设置与适用任务

- 客户端设置提供统一的自动刷新开关和刷新间隔，对当前客户端所有已授权任务生效，每任务独立计时。设置持久化。
- 未启动库存监控的任务也参与刷新；资料刷新成功不能自行启动购票。
- 初始授权后的完整业务流程成功作为首个计时起点；初始业务流程仍在执行时不另起定时刷新。后续以最近一次完整刷新成功时间加配置间隔安排下一轮。
- Go 后台统一调度，不依赖页面定时器。任务错峰，自动维护默认同时只执行一个任务；不限制不同任务的 N5 下单并发。
- 同任务最多一个维护流程；到期只保留一个待执行标记，不累计补跑错过的周期。

## 完整刷新内容

1. 重新获取小程序授权码。
2. 使用新 code 强制重新登录票务业务，取得新 token，不能退化成仅刷新观演人。
3. 重新获取观演人列表，按原选中 ID 保留选择，检查是否存在、可用及资料完整。
4. 重建订单人员快照，绑定本次业务 UID、code、token，并确认配套订单加密参数可用。
5. 全部成功后更新完整刷新成功时间；按维护前的运行意图决定是否恢复实时监控。

## 下单和维护边界

| 到期时状态 | 行为 |
| --- | --- |
| 已授权、库存未启动 | 刷新，完成后保持未启动 |
| 正在监控库存 | 记录运行意图，暂停本任务查询和未发送提交，再维护；其他任务继续 |
| 已命中完整方案、准备提交或等待密钥 | 优先完成本次提交，刷新标记待执行，不夺走已命中方案 |
| N5 请求在途 | 等待结果，不重新登录、不替换会话和人员快照 |
| 下单失败后的冷却阶段 | 可执行待刷新；冷却和维护均结束后才恢复查询 |
| 已创建订单、订单核实中、购票受限或需人工处理的暂停状态 | 暂缓自动刷新，不改变订单上下文，不自动解除暂停；人工处理完成后重新判断资格 |

- 自动刷新避让首次开售提交窗口，优先完成既定首次提交；不得因刷新改抽首次目标或意外触发默认库存提交。开售前避让的具体提前量不在本次确认范围内，实现时须明确成可验证边界。
- 维护恢复使用实时库存监控并重新匹配，不复用维护前的库存方案、不重新进入默认库存首次提交窗口。
- 暂停、发单门闩和维护准入通过同一状态入口互斥处理；已经发出的请求使用原提交快照收尾，不因刷新重复下单。

## 手动操作与取消

- 手动完整刷新（重新登录并获取观演人）成功后，重置下一次自动刷新时间，并消除已满足的待刷新标记。重新授权后的完整业务刷新成功同样计入。
- 若存在仅刷新观演人的入口，其成功不算完整刷新成功；完整刷新已到期时，待手动操作完成后再执行。
- 自动刷新中再次点击刷新，提示正在刷新，不并发启动或取消重来。
- 用户点击停止取消本次自动恢复购票意图；迟到维护结果不能重新启动库存任务。停止购票不会关闭全局自动刷新，后续仍可更新资料但保持购票停止。
- 解绑、删除任务、账号换绑或退出客户端登录取消相应调度与重试，旧结果不得写入新账号或恢复任务；不重新创建已删除任务。

## 失败与离线

- 网络或协议临时错误按退避重试，建议序列为 5 秒、15 秒、30 秒，随后维持较长间隔；不叠加并发刷新。重试期间完整刷新成功时间不推进。
- 新登录成功但观演人获取失败时保持维护失败，不能组合新 token 与旧人员缓存恢复下单。
- 已选人员缺失、不可用或资料不完整时阻止自动恢复并提示人工处理，不自动换人或减少人数。
- 沿用现有协议离线／授权失效宽限规则。定时到期本身不得清除仍允许使用的旧参数；协议恢复后按维护流程刷新。
- 自动维护失败保留维护前运行意图，重试成功且全部条件满足后才恢复；用户停止会清除该意图。

## 设置变化与重启

- 关闭开关取消未开始的自动维护和自动重试；已开始的维护完成收尾，避免会话更新一半。显式停止仍优先于自动恢复。
- 修改间隔按各任务最近完整成功时间重新计算；已到期任务进入错峰队列，不同时爆发。
- 客户端重启不恢复购票执行或维护前运行意图。已授权任务在客户端登录、会话及协议条件满足后可恢复资料维护调度，不自行启动购票。
- 展示上次完整成功、下次安排、待刷新／维护中／失败原因；未完成的刷新不展示为成功。全局间隔的默认值、有效范围以及错峰幅度在实现时明确，不作为官方会话有效期保证。

## 验收重点

- 全局开关覆盖已授权的运行及未运行任务；初始授权流程不与定时器重复。
- 每次自动刷新确实重新取 code 和登录；成功计时不被局部步骤或失败推进。
- 定时与手动、库存命中、首次提交、在途订单竞争时没有双重维护或重复发单。
- 已创建／待核实／受限暂停不会被自动维护解除；冷却不能被刷新缩短。
- 原选中人员失效及局部刷新失败阻止恢复；新旧会话、人员和密钥不混用。
- 维护期间停止、解绑、删除、退出及换号后的迟到结果无效；重启不自动购票。
- 调度和时间边界使用可控时钟及本地协议／业务桩测试，不依赖官方在售比赛。
